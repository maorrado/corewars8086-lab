# Night session materials — 2026-09-28

This directory holds the research output from an overnight investigation
into whether `final/`'s promoted `m049` pair (Chimera A/B) could be
improved. **No candidate beat m049 on a fresh holdout; `final/` was not
changed.** Read `progress-2026-09-28.md` first — it has a full summary at
the top, followed by the detailed chronological working log.

## Layout

- `progress-2026-09-28.md` — the full write-up: methodology, findings,
  every candidate direction tried, and why each was rejected.
- `configs/` — `official-benchmark.mjs`-compatible JSON configs for every
  screen/tune/holdout run referenced in the report. Each config's
  `candidate.warriors` field points at a compiled binary path under
  `build/...` that is **not** included here (binaries are reproducible, see
  below); `cohorts[].opponents[].warriors` point at
  `official-2025/survivors-online/...`, which already exists in this
  branch.
- `results/` — compact JSON summaries of every run (aggregate + per-run
  scores + candidate binary SHA-256, with local file paths and raw stdout
  stripped out). `results/index.json` is a flat index of all of them.
  `results/telemetry-analysis-m049-all2025.json` is the processed death-cause
  breakdown referenced throughout the report; `results/chimera-*-round*.{json,png}`
  are single-battle arena-state snapshots from `inspect-arena.mjs`.
- `patches/debug-trace-instrumentation.patch` — the minimal diagnostic patch
  (one method, ~30 lines) applied to a copy of
  `repos/corewars8086-6.0.0-deterministic` to print per-death byte dumps.
  Does not alter CPU/War/scoring semantics.

## Reproducing a result

1. **Assemble the candidate source.** All tested `.asm` sources are in
   `candidates/generated/chimera-{al-sweep,anchor-sweep,refresh-rate,decdi-test}/`.
   The two new sweep families also have generator scripts at the repo root:
   `generate-chimera-al-sweep.mjs`, `generate-chimera-anchor-sweep.mjs`,
   `generate-chimera-refresh-rate.mjs` (run `node generate-chimera-*.mjs` to
   regenerate the `.asm` files from scratch). Then:
   ```
   node assemble.mjs <output-dir> candidates/generated/<family>/<name>.asm final/ChimeraB.asm
   ```
   (some variants replace `ChimeraB` too — check the specific config's
   `candidate.warriors` field). Requires the local simulator server running
   at `http://127.0.0.1:8123/page.html` (serve
   `repos/corewars8086_js/war/`) plus Chrome, per the lab's existing
   `assemble.mjs` requirements.
2. **Point the config's `candidate.warriors` at your freshly built
   binaries** (edit the path, or reproduce the exact `build/...` layout used
   originally — visible in each `results/*.json`'s `runs[].candidate` /
   binary SHA-256 fields for verification).
3. **Run**: `node official-benchmark.mjs study-notes/night-session/configs/<name>.json`
   — compare the printed `aggregate.teamPerBattle` against the corresponding
   entry in `results/index.json`.
4. **For the debug-trace byte dumps**: apply
   `patches/debug-trace-instrumentation.patch` to a fresh copy of
   `repos/corewars8086-6.0.0-deterministic`, rebuild with
   `mvn -q clean package -DskipTests` (JDK 8 required — the lab already
   vendors one under `tools/temurin8-jdk/`), then run the resulting jar
   headless exactly as `official-benchmark.mjs` does (see the patch's
   header comment).
