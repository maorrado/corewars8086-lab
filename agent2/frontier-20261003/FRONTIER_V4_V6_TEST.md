## Frozen plans

Each plan has the same eleven arms: m049, m050, e1p3, e1p4, b01d,
combo_zrl03, combo_ah02, Good_Test_V4, Good_Test_V6, zchain3, zchain4.
Every arm is loaded as team `CAND` against the **same** three-opponent cohort,
seed and Zombie pack, so the score differences are paired. The 2025 opponent
pool is the 75 published online teams, not a prediction of the 2026 final.

| Plan | Field | Zombies | Battles per arm | Purpose |
| --- | --- | --- | ---: | --- |
| `frontier-v4-v6-screen.json` | 2025 online, 1 partition | 2025 live | 1,000 | Selection / exploration |
| `frontier-v4-v6-holdout.json` | 2025 online, 4 independent partitions | 2025 live | 4,000 | Fresh-seed confirmation |
| `frontier-v4-v6-nozombies.json` | 2025 online, 2 partitions | none | 2,000 | Zombie-dependence stress |
| `frontier-v4-v6-2024live.json` | 2024 live, 2 partitions | 2025 live | 1,120 | Opponent-population stress |

All plans have unique salts and are already generated. Before running, check
the frozen identities and plan structure with:

```powershell
node agent2/frontier-20261003/verify-frontier.mjs
```

Read `agent2/tools/bench.mjs` before use. That runner reuses existing
`scores.csv` files for a plan ID; never change an arm's bytes or a plan under
an existing ID after any run. If inputs change, create a **new** plan ID and
salt instead of relabeling old results.

Example commands from the repository root (choose a thread count that does
not overload concurrent research jobs):

```powershell
node agent2/tools/bench.mjs agent2/frontier-20261003/frontier-v4-v6-screen.json --threads 4 --engine persistent
node agent2/tools/compare.mjs agent2/results/frontier-v4-v6-screen-persistent.json m050 --by-opponent
```

Run the holdout only after recording which comparison(s) the screen selected
and a decision rule. Do not select a winner by looking at all eleven holdout
scores and then call the selected difference a pristine 95% finding; account
for the multiple comparisons or run a further fresh confirmation. Use paired
cohort differences and uncertainty, inspect both warriors, and separately
report V4 versus V6, winner versus zchain3/zchain4, and regressions against
specific opponents. A field average and a direct duel answer different
questions. If the interval crosses zero, say that the test is inconclusive.

The persistent driver uses the unmodified deterministic v6 JAR but is still
research tooling. Check any decisive result with a fresh or sampled
`--engine original` run and verify byte-identical `scores.csv` for matching
jobs. Do not claim superiority for unknown 2026 opponents or Zombies.

No result has been generated by this package yet; the JSON files define tests
for the second agent to execute and analyze.
